# 移动端适配 · 验收清单（第一批）

> 适用范围：第一批（竖屏提示 / 字号下限 / 44px 热区 / 触摸行为 / 后台暂停 / 返回键兜底）。
> 目标：PC 端零回归，手机横屏原生可玩，竖屏只做提示。
> 标记：`[自动]` 可一键跑；`[人工]` 需真机肉眼/手感确认。

## 一、一键命令

```bash
# 1) CSS 静态断言（媒体查询分层、字号写法、热区归属）
node js/dev/css-audit.js

# 2) 可暂停定时器单测（Node 虚拟时钟）
node js/dev/timer-test.js

# 3) 出题自检（42 关 × 30 次）
node js/dev/selfcheck.js

# 4) 运行时行为验证（倒计时冻结/恢复、结算定时器暂停、返回键）
node js/dev/capture.js /tmp/pc --verify-behavior 1

# 5) PC 视觉回归：出图 + 与基线逐像素比对（必须 0 差异）
node js/dev/capture.js /tmp/pc
node js/dev/pixel-diff.js js/dev/baseline/pc1920 /tmp/pc

# 6) 手机横屏断言（844×390 / iPhone SE 667×375）
node js/dev/capture.js /tmp/ms --width 844 --height 390 --mobile 1 --assert-mobile 1 --dpr 2
node js/dev/capture.js /tmp/se --width 667 --height 375 --mobile 1 --assert-mobile 1 --dpr 2

# 7) 竖屏提示断言（390×844）
node js/dev/capture.js /tmp/pt --width 390 --height 844 --mobile 1 --assert-mobile 1 --dpr 2
```

`--mobile 1` 用 CDP `Emulation.setTouchEmulationEnabled` 让 `pointer: coarse` 生效，等价于触屏设备。

## 二、PC 回归（必须全绿）

- `[自动]` 1920×1080 六屏（开始/地图/关卡/结算/商店/皮肤）与 `js/dev/baseline/pc1920` **逐像素 0 差异**（tolerance=0）。
- `[自动]` 六屏关键元素计算样式快照与基线一致（见 `pixel-diff` 第二个区块）。
- `[自动]` 页面无 JS 报错。
- 基线不接受的变更：任何在 PC 上生效的字号/尺寸/间距/颜色改动。新增规则必须落在媒体查询内。

### 触控本（any-pointer: coarse + pointer: fine）

没有 Windows 触控本，真机部分**不冒充已验**，按「静态断言 + 代码审查」降级：

- `[自动]` `css-audit` 保证：字号规则只存在于 `(pointer: coarse)` 且写在 `mobile.css`；`touch-action`/`-webkit-touch-callout`/热区伪元素只存在于 `(any-pointer: coarse)`；`:hover` 必须 `(hover: hover) and (pointer: fine)`。
- `[自动]` PC 基线 diff 0（纯鼠标路径）。
- `[人工/待补]` 触控本上 `.pager-arrow` / `.btn-tool` **允许 1~2px 视觉差异**：这两处 `::before`/`::after` 已被玻璃高光占用，且父级 `overflow: hidden` 会裁掉向外扩的伪元素，因此改为元素盒补足（`min-width/min-height`）。`any-pointer: coarse` 命中时盒子变大 1~2px，属预期，不视为回归。
- **实际热区尺寸**（元素盒，无伪元素参与）：`.pager-arrow` **44×40**、`.btn-tool` **44×44**、`.btn-back-game` 元素 24×24 + `::after` 44×44 → 有效 44×44。
- `[自动]` 断言底线：`.pager-arrow` 宽高均 ≥40（业务底线 ≥38）；`.btn-tool` / `.btn-back-game` ≥44。
- `[自动]` 该差异不得挤压排版：道具方块两两不相交、箭头不压页点、箭头不压商品卡、货架可视宽度 A/B 一致（去掉 `min-width` 后宽度不变）。

## 二之二、触摸端货架密度（最终参数与实测）

最终参数（全部在 `@media (any-pointer: coarse)` 内；PC 不命中，基线 diff 0）：

```css
.shelf-page   { padding-top: 2px; padding-bottom: calc(1cqw + 34px); }
.pager-arrow  { min-width: 44px; min-height: 40px; }   /* 字形不变，只留 40 高 */
.layer        { padding-bottom: 11px; }                 /* 原 1.35cqw */
.layer-grid   { padding-top: 1px; padding-bottom: 1px; } /* 原 .35cqw */
.slot         { padding-top: 0; padding-bottom: 0; }    /* 归零，2px 全给图片区 */
.slot-frame   { padding: 0; }                           /* 原 .22cqw */
```

### 关键模型（务必记住，已被两次实测校正）

- **卡高只由容器决定**：`.layer-grid` 行高 `minmax(0,1fr)`，卡片拉伸填满；`.slot`/`.slot-frame` 内边距只在卡内重新分配。
- **`gapBoard`（卡底→层板顶）= 层 padding-bottom + 网格 padding − 层板高(1.25cqw)**。负值即卡片压进层板。
- **卡高 = C0 − Δ(层 padding) − 2×Δ(网格上下 padding) − Δ(页面留白)/3 + Δ(页面 padding-top)/3**
  → 页面留白 3 层均分（1/3），层 padding 1:1。**两者不对称**：页面 −3px 只能补 +1px/层，层 padding +3px 直接吃 3px。
- **图片区 = 卡高 − 文字与边框固定高度 − 2×slot padding** → `slot` padding 是唯一「不动卡高、只换图片区」的杠杆。
- **箭头间隙 = gapBoard + (页面留白px − 37) + 8.66**
  → 抬 gapBoard 3px 会自动把箭头间隙也抬 3px，留白可再降 3px。

### 实测（headless + CDP 触摸模拟，关卡 25 = 3 层 × 4 件）

| 视口 | 件数 | 商品卡（现 / 改前） | 图框盒 | 图片区（断言 / 内部量） | 卡距层板 | 箭头↔价格行 | 箭头热区 | 层间距 | 横间距 |
|---|---|---|---|---|---|---|---|---|---|
| 844×390 | 12 | **59.9** / 61.2px | 33.7px | 29.4 / 29.74px | **3.34px**（改前 −0.66，压在层板上） | **9.0px** | 44×40 | 13.0px | 5.5px |
| 667×375 | 12 | **56.6** / 57.8px | 30.8px | 26.3 / 26.83px | **3.67px**（改前 −0.33） | **9.0px** | 44×40 | 13.0px | 5.3px |

- 图片区相对改前**不降反增**（+0.72px），卡高让渡 1.28px，文字行/描边/字号均未动。
- 状态：844 与 667 均 **40/40 断言 PASS**。

### 可选补偿（未实施，等真机确认）

若真机觉得 `.slot` padding 归零后图片/价格胶囊太贴卡片内壁：

| 手段 | 844 图片区 | 667 图片区 | 844 卡高 | 说明 |
|---|---|---|---|---|
| 现状（`slot` padding 0） | 29.4 | 26.3 | 59.9 | — |
| `.slot{padding-top:.5px;padding-bottom:.5px}` | ≈28.4 | ≈25.3 | 59.9（不变） | 卡高不受影响，仅图片区 −1px，仍 ≥24 |

若真机觉得 667 卡高（56.6）太扁：**只给 667 单独参数，不动 844**，例如把 `.layer` padding-bottom 由 11 回退 1~2px（卡距层板 3.67→1.7~2.7 仍为正），或把留白 34 抬回 36；不要把 C 案（grid padding 归零）拿来换 844。

注意：**卡高 62 在 667 上无论怎么调都到不了**（除非层 padding 归零使卡与层板重叠、或减件数/降字号，均被底线禁止），上限约 58.9。

### 与 P1（安全区）的联动要求

P1 引入 `env(safe-area-inset-*)` 后，必须复跑：
- `翻页箭头热区不压商品卡`
- `卡片不压层板`（要求 3~4px；安全区若改变货架高度/内边距会直接动到它）
- `留白可下调余量`（当前 9.0px，只余 1px 可下调；**这是 B 案留给 P1 的全部余量，不得再挪**）
- `44px 热区不压缩货架`、`关键尺寸`（12 件仍完整可见）、PC 基线 diff 0
禁止 P0 调完密度、P1 又把价格行压回去。

**每改一次留白、层/网格 padding 或 slot padding，都必须重跑 `--assert-mobile` 的这四项断言。**


## 二之三、圆角控件的角点命中

`.btn-tool` 热区 44×44，但自身 `border-radius: 2.8cqw`（844×390 下 19px）；`.pager-arrow` 无圆角。

实测自真角点沿对角线向内多少像素才命中：

| 控件 | 圆角 | 四角需内缩 | 理论值 |
|---|---|---|---|
| `.btn-tool` | 19px | 6 / 0 / 5 / 5 px | 6px |
| `.btn-back-game` | 12px | 3 / 3 / 3 / 0 px | 4px |
| `.pager-arrow` | 0px | 0 / 0 / 0 / 0 px | 0px |

结论：角点点不到是**控件自身圆角**（命中区域=圆角矩形）导致，不是父级 `.shelf` / `.stage` 的 `overflow: hidden` 裁剪。
按 44px 宽/高（包围盒）计已达标；若真机要求角点也能点，需在 `(any-pointer: coarse)` 下把 `.btn-tool` 圆角降到 8~10px（仅触摸端生效，PC 不受影响），其余视觉不变。

## 三、手机横屏（可玩性）

- `[自动]` 39 项断言：字号下限逐项、`scrollWidth ≤ clientWidth` 逐项（商品名 23、价格 23、品类行 2、清单行 2、清单标题 1，**不抽样**）、热区尺寸/四角在舞台内/命中、挤压断言、关键尺寸与留白可下调余量、圆角控件四角内缩、竖屏提示不出现。
- `[自动]` 热区四角坐标输出示例（844×390，舞台 `(75,0)–(769,390)`）：
  - `.btn-back-game`：元素 24×24，`::after` 44×44，热区 `(89,14) (133,14) (89,58) (133,58)`，四角均在舞台内，圆角 12px 内缩 5px 后 4 角 + 中心 5/5 命中。
  - `.pager-arrow`：热区 **44×40**（宽未变、高由 44 降为 40），四角 `(361,335) (405,335) (361,375) (405,375)`，5/5 命中；宽高均 ≥38 底线。
  - `.btn-tool`：热区 44×44，四角 `(609,7) (653,7) (609,51) (653,51)`，5/5 命中。
  - 说明：圆角控件的**真角点落在圆角透明区**，不参与命中；命中判定按圆角内缩后的 4 角 + 中心。若某角超出舞台被裁，断言会输出裁剪后的实际有效尺寸。
- `[人工]` **可读性**：667×375 与 844×390 真机上肉眼确认 10px 档（品类说明行、品类限制行、商品名、道具小字、角标）可读。
  - 溢出断言只能证明「没被裁断」，**不等于可读**。
- `[人工]` 商品图放大后手指点选准确率、连点两次取消、翻页箭头点按手感。

## 四、竖屏（只验提示层）

竖屏不提供可玩布局，只展示「把手机横过来玩吧」提示层。

- `[自动]` 提示层 `display: flex`、卡片完整在视口内（390×844 实测 335×251 @ (27,296)）、关闭按钮可见。
- `[人工]` 真机确认提示层文案 18px（标题）/14px（正文）可读，「仍要继续」按钮可点。

## 五、后台与动画（冻结语义，统一口径）

- **关卡倒计时**：切后台冻结（停表），回前台按剩余时长继续，不补偿后台时间。
- **结算 / 存钱罐动画**：切后台暂停、回前台继续（不是「后台跑完」，也不是「不冻结」）。实现上用 `ZQ.timer.*` + `body.is-paused` 暂停 CSS 动画。
- `[自动]` `--verify-behavior` 覆盖：`切后台倒计时冻结`、`is-paused` 生效、`animation-play-state=paused`、`回前台倒计时继续`、`后台期间结算定时器不跑`、`回前台后结算定时器补跑`。

## 六、返回键（Android / 手势返回）

策略：**屏幕级切换才入栈**，弹窗只关弹窗不跳屏。

- `[自动]` 弹窗（结算 / 存钱罐 / 设置 / 聚光提示）不调用 `ZQ.app.go()`，由 DOM 开关控制。
- `[自动]` 地图 → 开始：`go()` 用 `replaceState`，地址栏与画面一致，不形成「返回→再进」循环。
- `[自动]` 开始页首次返回：拦截 + 补一条历史（条目不增不减）+ 弹「再按一次返回键退出游戏」；2.5s 窗口过期后再次按会重新提示。
- `[人工]` 真机确认：
  - 大厅 → 地图 → 返回 → 停在开始页，不是空白页；
  - 地图 → 关卡 → 返回 → 回到地图，不是直接回大厅；
  - 开始页 2.5s 内连按两次 → 按浏览器行为退出（页面内无法断言退出本身，只能真机看）；
  - 地址栏 hash 是否稳定（不被重载刷掉）。
- 已知限制：若用户手动输入 URL 进入，本页就是历史栈第一条，跨文档返回无法被 JS 拦截，不属于本实现缺陷。

## 八、已知限制（非缺陷）

- `file://` 下妈妈立绘环境光（`mask-image`）会报 `CORS policy`，图像主体正常；`http://` 下无此报错。
- 圆角控件的热区真角点不可命中（圆角透明区），命中按内缩判定。
